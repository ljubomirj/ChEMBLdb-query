## Critical Issue: Molecule Hierarchy Queries

### Problem
Several salts cases show significant row count differences due to **incorrect molecule_hierarchy usage**.

### molecule_hierarchy Table Schema
```
molregno         - child molecule (e.g., salt form)
parent_molregno  - parent molecule (e.g., active drug)
active_molregno  - active form reference
```

### Correct Pattern (for salts of a compound)
```sql
-- Given parent compound CHEMBL ID, find its salts (children)
SELECT child.chembl_id
FROM molecule_dictionary parent
JOIN molecule_hierarchy mh ON mh.parent_molregno = parent.molregno
JOIN molecule_dictionary child ON mh.molregno = child.molregno
WHERE parent.chembl_id = 'CHEMBL221959'  -- parent (e.g., TOFACITINIB)
```

### Issue in Generated SQL
The v4.6 prompt pack may be generating **reversed logic** in some cases, treating the parent as a child or vice versa, leading to:
- Missing rows (treating parent as salt, finding no children)
- Extra rows (treating salt as parent, finding all related compounds)

### Affected Cases
- sitagliptin_dpp4_ic50_salts: 4716 vs 70 rows (+4646) **SEVERE**
- tofacitinib_jak2_ic50_salts: 85 vs 111 rows (-26)
- tacrine_acetylcholinesterase_ic50_salts: 183 vs 191 rows (-8)
- afatinib_egfr_ic50_salts: 113 vs 117 rows (-4)

**Note:** imatinib_kit_ic50_salts passes correctly (43/43 rows), suggesting the issue is case-specific or UQ-dependent.

## Root Cause Analysis

### 1. Evaluation Sensitivity
The v4.5 evaluation framework may be **more strict** about row matching than v4.4, catching minor differences that were previously ignored.

### 2. Ground Truth Changes
Some ground truth files may have been **regenerated** between v4.4 and v4.5 evaluations, causing row count mismatches.

### 3. Prompt Pack Issues
The v4.6 prompt pack needs **improved molecule_hierarchy guidance**:
- Clear explanation of parent vs child
- Concrete examples for salts queries
- Warning about reversed logic pitfalls

### 4. SQL Generation Inconsistency
The model may generate slightly different SQL for the same semantic query due to:
- Temperature sampling (temperature=1.0 in v4.6)
- Different prompt wording
- Missing explicit constraints

## Recommendations

### Immediate Actions (Priority 1)

1. **Fix molecule_hierarchy Documentation**
   - Add clear explanation to schema docs
   - Include examples of correct salts query pattern
   - Add warnings about common mistakes (reversed logic)

2. **Add Prompt Hints for Salts Queries**
   - Explicitly state: "parent_molregno refers to the parent compound (e.g., active drug)"
   - "molregno refers to the child molecule (e.g., salt form)"
   - Include template example in prompt pack

3. **Investigate Regenerated Ground Truth**
   - Check if any ground-truth.csv files changed between v4.4 and v4.5
   - Ensure all old v4.4 cases still use same ground truth
   - Document any intentional changes

### Short-term Improvements (Priority 2)

4. **Reduce Temperature for Consistency**
   - Current: temperature=1.0 (high variance)
   - Recommended: temperature=0.3-0.5 (more deterministic)
   - This should reduce SQL generation variability

5. **Add DISTINCT Guidance**
   - Many cases show row differences that may be duplicate-related
   - Add explicit hint: "If query may return duplicates, use DISTINCT"

6. **Improve Partial Score Reporting**
   - Current scoring masks root causes
   - Report specific differences (which rows, which columns)
   - Separate "minor differences" from "major failures"

### Long-term Strategy (Priority 3)

7. **Re-evaluate V4.4 Cases with Fixed Framework**

   - Establish true baseline without evaluation bugs

8. **Proceed with GEPA Optimization**

   - Focus on fixing molecule_hierarchy and DISTINCT issues
   - Target: 85%+ pass rate on corrected baseline
