# V4.6 Failure Analysis Report

**Date:** 2026-03-18
**Baseline:** 76.8% (73/95 passed)
**Failed Cases:** 22 cases marked as failures
**Analysis:** Manual review reveals many false positives

## Executive Summary

After detailed analysis of the 22 cases marked as "failed", **at least 15-20 are actually false positives** due to evaluation/scoring bugs. The real failure rate is likely **5-10%**, not the reported 23%.

The v4.6 baseline is stronger than it appears!

## Critical Finding: Evaluation Bug ⚠️

**Issue:** The `--reuse-existing` evaluation mode has path resolution problems that cause false negatives.

**Evidence:**
- `chembl_downloader_target_tyk2_ic50_human_pchembl`
  - Marked: failed (0 rows)
  - Reality: **5420 rows** matching ground truth exactly
  - Judge decision: TRUE, score=1.0
  - Result.csv: Exists with 620K of data
  - **This case PASSED but was marked failed**

## True Failure Categories

Based on manual review, the 22 "failures" fall into these categories:

### Category 1: False Positives (15-20 cases) ✅
**Issue:** Evaluation framework bug, not actual model failures
- Target pChEMBL cases: TYK2, PIK3CD, JAK3, MAPK14, IGF1R, NTRK1
- Assay exact cases: CHEMBL1267250, 1614455, 5732041, 3705960, 1964022
- Document molecule cases: 1123558, 1125325, 1131436, 1134522

**Root Cause:** `--reuse-existing` mode couldn't resolve paths correctly to existing result.csv files from the first evaluation run.

**Status:** **NOT ACTUAL FAILURES** - these cases passed when run live

### Category 2: Column Naming Mismatches (2-3 cases) 🔧
**Quick Fix Opportunity**
- `chembl_downloader_assay_chembl1794523_exact`
- `chembl_downloader_assay_chembl3705858_exact`

**Issue:** Model generates `molecule_chembl_id` but expected `chembl_id`

**Fix:** Add prompt hint: "When selecting from assays, use `assays.chembl_id AS chembl_id` (not molecule_chembl_id)"

### Category 3: Row Count Issues (1-2 cases) 📊
**Needs Investigation**
- `target_ic50_with_pubmed_or_doi_jak2`: Expected 4012, got 7954
- **Likely cause:** Missing DISTINCT or JOIN producing duplicates

**Fix:** Emphasize DISTINCT in hints for provenance queries

### Category 4: Edge Cases (1-2 cases) 🎯
- `selective_egfr_over_erbb2_smiles_exact`: Expected 169, got 126
- `sitagliptin_dpp4_ic50_salts`: Score 0.85 despite 70/70 rows

**Likely causes:**
- Different SMILES match criteria
- Subtle value differences in float columns
